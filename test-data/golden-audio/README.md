# Golden audio corpus

Per Milestone C task 5: at least 12 clips across 2-3 approved passages
covering clean-correct, single-word omission, repetition, substitution,
noisy, too-short, and silent cases.

## What's here: non-recitation clips only

| File | What it is | Generated by | Expected quality-gate outcome |
|---|---|---|---|
| `silent.wav` | 3s of digital silence | `generate_non_recitation_clips.py` | fails: `mostly_silent` |
| `white_noise.wav` | 3s of Gaussian white noise (σ=0.3) | `generate_non_recitation_clips.py` | fails: `noisy` (SNR below floor) |
| `too_short_tone.wav` | 0.2s, 440Hz tone | `generate_non_recitation_clips.py` | fails: `too_short` |
| `clipped_tone.wav` | 2s, 440Hz tone at 3x amplitude (hard-clipped) | `generate_non_recitation_clips.py` | fails: `clipping` |

Regenerate with:
```
services/inference/.venv/bin/python test-data/golden-audio/generate_non_recitation_clips.py
```

Each file is a real, valid 16kHz mono 16-bit PCM WAV (verified with `file(1)`
after generation) — no fabricated/fake binaries per CLAUDE.md Principle 7.
None of these are Quran recitation, or anything resembling speech at all;
they exist solely to exercise `services/inference/app/audio_quality.py`'s
quality gate, which is pure signal processing and has no ML/recitation
content in it to fake.

## What's NOT here: recitation clips — BLOCKED, human-owner task

Per CLAUDE.md's Stub Policy and the Milestone C instruction ("never
synthesize recitation audio"), the following clips are **not** included
and cannot be legitimately produced by this session:

- Clean, correct recitation of an approved MVP passage (e.g. Al-Fatihah or
  An-Nas — see `docs/backlog.md` Milestone B's MVP passage set).
- Deliberate single-word omission.
- Deliberate word repetition.
- Deliberate word substitution.
- A noisy-but-otherwise-correct recitation (background noise over real speech).

**Why this is blocked**: producing these requires either (a) a real human
reciting the passage under an explicit, purpose-specific consent record
(CLAUDE.md Principle 6 — raw recordings require consent before any
model-training/evaluation use), or (b) text-to-speech synthesis of Quranic
text, which CLAUDE.md explicitly forbids ("never fake 'recitation'"). An AI
assistant cannot legitimately generate consented human recitation audio,
and must not synthesize speech audio of Quranic text as a substitute.

**Unblocking condition** (human-owner task, also listed in the project
README's "Human-owner tasks Claude Code cannot do for you"): a qualified
human — ideally with some tajweed proficiency, so the deliberate-error
clips are realistic — records:
1. 2-3 clean, correct recitations of different approved passages.
2. For one of those passages, 3 variants with a single deliberate error
   each: one word omitted, one word repeated, one word substituted for a
   phonetically different word.
3. One recitation with realistic background noise (fan, traffic, etc.)
   layered under otherwise-correct speech.
4. A signed, purpose-specific consent record permitting this specific use
   (golden-corpus evaluation, per Principle 6) before any clip is added
   here.

Until then, `services/api`'s golden-corpus integration test
(`services/api/scripts/goldenCorpusIntegration.ts`) only proves: (a) the
quality gate correctly rejects every non-recitation clip above, and (b) the
full pipeline — real HTTP call to the real running `services/inference`
ASR checkpoint, forced alignment, deviation candidates, feedback policy —
executes end-to-end without any stub in the path. It does NOT (and
currently cannot) prove alignment *accuracy* on real recitation, because
no consented recitation audio exists to test against. See the milestone's
risk notes for the full implication of this gap.
